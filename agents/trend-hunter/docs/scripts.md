# Scripts

What each file of this repository does, with the task that introduced it. The
overview is the [README](../README.md); the order in which the stage runs them is
[`SKILL.md`](../.claude/skills/trend-hunter/SKILL.md). The sections an entry
points to with "below" are in [`sources-and-candidates.md`](sources-and-candidates.md)
and [`selection.md`](selection.md).

## Layout

- `.claude/skills/trend-hunter/SKILL.md` — the agent's instructions (RSS discovery, YouTube signal, score, reason about scenes, write output)
- `scripts/` — mechanical data-fetching (`fetch_youtube_signal.py`, `fetch_rss_news.py`) and the calibrated scoring scale (`score_candidates.py`; its `--houses` takes `--rss <fetch output>` and attributes a link to the house of the feed that carried it, the domain only as fallback, a link nothing places listed in `unattributed_links`, never a crash - CF-0753, Hacker News' off-site links on example-tech 2026-10-15T1854Z) — no LLM reasoning here, just API calls and arithmetic, plus `evidence_sources.py`, which fills and checks `evidence.sources[]` in a batch (CF-0071: per `rss_links` entry the headline, masthead, date and feed URL as the fetch recorded them - a source with `title` or `published_at` null is unusable for a proof; since CF-0533 also the RSS `summary` - since CF-0638 only of a `read_text` feed, `null` for a `headline_only` one), and `check_scenes.py` (CF-0533), which holds every scene to one source of its topic (`source_url`; the proper-name and who-did-it checks against the headline were retired by CF-0556), refuses a description whose amount the shell ate (`figure_lost`, CF-0736: «.5 million» for its source's «$27.5 Million», after an unquoted heredoc on example-film 2026-10-13T1411Z) and judges the fact against the scenes (CF-0548); a violating scene moves to `scenes_dropped[]`, a topic left without scenes gets the `general` scene built from a headline; its `--check` also runs `skipped_codes.py` (CF-0708), which refuses a `skipped_topics[]` `reason_code` outside the root funnel's `FUNNEL_CODES` - a coined `no_dated_source` reached the funnel as an unknown code on example-science 2026-10-12T2001Z - and an old word the funnel only reads in old batches - a code this repo's scripts write themselves (read from their code by `stage_codes()`, e.g. `footage_evidence_quota`) always passes; and `fetch_rss_news.py` reads an RSS 1.0 entry's `dc:date` as its date since CF-0708) CF-0789: `fetch_rss_news.py --channel` without `--days` reaches back the channel's `sources.rss.discovery_days` (default 3, bounds 1-14) and says so in `requested_days_from`; the skill writes the fetch to `<batch>/work/rss.json`.
- `scripts/fact_probe_topics.py` — CF-0264: the fact at topic selection. A person-topic is its own story (CF-0439) and is looked up for the work its news name or else for the person, never for a work from a filmography; every candidate's article is resolved through `agents/content-researcher/scripts/fact_probe.py` in score order, its fact candidates are searched (`fact_search.py`) and checked by the one fact rule below, and the first `scope.shortlist_size` (8) survivors are carried with `fact_candidates`; everything else is a `skipped_topics[]` record with a code. See "The fact decides the selection" below. CF-0812: every probe request carries `news` - the topic's own text (tech `tool`/`model`, title, scene descriptions, the leads' headlines and RSS summaries; `topic_news`, at most `NEWS_CAP` = 4000 characters; none for a person-topic) - so the probe's edition check holds an edition-qualified article ("Tesla Roadster (first generation)") to what the news name; it is not stored under `fact_probe.asked`. A `no_fact` row whose article was refused as another edition says so in its `reason` ("about another edition than the topic's own news"). Tests: `tests/test_probe_news.py`
- `scripts/candidate_pool.py` + `config/common_words.txt` — CF-0772: ExampleTech's candidate pool (step 2). `build` reads the whole `fetch_rss_news.py` output and writes `<batch>/work/candidate-pool.json`: every entry that names a product, a model or a company is a candidate (the name off the headline's capitals, inner capitals and model numbers; a Title Case headline or a headline's first word counts a word only when the batch, or the shipped vocabulary, never writes it in lower case), entries naming one subject are one candidate (equal names, or one product name inside another), shop offers and entries naming nothing are dropped and counted. Houses are counted by the feed that carried the entry; a `kind: vendor` feed (a company's own newsroom, the root's CF-0770) adds no house, its post stays in `rss_links` / `vendor_links`. Order: houses, entries, product before two names before one company, newest. `list` prints the pool a line a candidate; `mark` records the operator's scores, topic ids and `out_of_scope` reasons (the refill skips those). Other channels: refused (exit 2), their pool is the operator's.
- `scripts/refill_topics.py` — CF-0756: the refill to the target (step 5a+). After every `fact_probe_topics.py --write` pass it decides whether another round runs over the same candidate pool (`<batch>/work/candidate-pool.json`, written by the operator at step 5: every candidate step 2 found, `popularity_score` null for the unscored), which unscored candidates it takes (best RSS signal first, never one the batch has judged or an earlier round took, fresh `topic_id`s) and how many (the first pass's yield, spread over the rounds left, within the cap, the day's quota less one facet run per target topic, and the pool). Stops on `target_met` / `pool_empty` / `rounds` / `search_cap` / `quota` and writes the batch's `refill` block (`rounds`, `searched`, `added`, `stopped_because`, `below_min`, `round_log`, `summary_line`). The channel's numbers are `scope.target_topics` (5), `scope.min_topics` (3), `scope.max_refill_rounds` (3), `scope.max_refill_search_calls` (40) - defaults when absent. Tests: `tests/test_refill_topics.py` (stand-in scorer, probe and fact search; no network) CF-0789: a second target, `scope.min_scored_candidates` (default 12, ExampleFilm's floor): the refill does not stop on `target_met` until the probe has judged that many candidates over every pass (`refill.scored`), a round sized by the batch's pass rate; `refill.sources` records where the candidates came from (per feed: entries, requests; per house: candidates, out of scope, evaluated, scored, viable) and what they cost (scoring search calls and API units).
- `scripts/promote_below_shortlist.py` — CF-0882: step 5b for topics from below the shortlist, on the root's refill round (`shared/below_shortlist.py`, seam `footage`), never by hand. `<batch> --topics a,b --max-searches K --result <path>`: per topic the feeds first (0 searches when they cover it), the channel's facet run only when they do not (`fetch_youtube_signal.run_signal`, capped: a run the rest of `K` does not pay for is not made, `quota`; the cache's answers are free - `calls_needed` / `search_cache.Cache.peek`), then `footage_candidates._walk_substitute`. A pooled topic moves into `topics[]` marked `refill` with its `rank`; a refused one keeps its `below_shortlist` row with `refill_outcome: refused`; every topic is a row of `below_shortlist_refill[]`, the spend goes into `search_quota`. Result `{topics: [{topic_id, outcome: candidates|refused|quota|error, searches, reason}]}`. A second call for the same topic searches nothing. See [selection.md](selection.md).
- `scripts/pool_coverage.py` + `scripts/pool_screen.py` — CF-0325: what `shared/footage` already holds for a topic, by title / franchise / earlier topic, screened with the Video Editor's pre-cut gate (via `footage-indexer/scripts/pool_depth.py`, under the indexer's venv) minus retired shots; `fact_probe_topics.py` cuts the shortlist on `popularity_score × (1 + 0.5 × coverage)` and writes `topics[].pool`. `scripts/pool_coverage_replay.py` replays it over the frozen batches.
